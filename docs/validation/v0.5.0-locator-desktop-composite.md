# 定位环桌面合成验收

2026-09-14，生产代码不变，新增 LocatorDesktopCompositeTests。

此测试在自有不透明窗口上显示实际 LayeredCursorOverlay.ShowLocator，不只是调用 DrawLocatorRing 生成内存图片。捕获区域限制在自有背景客户端内，显示环前逐像素确认背景完全纯色；若被其他窗口遮挡则失败，不保存该背景截图。测试不移动或隐藏系统鼠标、不修改系统设置。

**测试隔离问题已解决：** 起初单独运行通过，与 Platform 全套一起运行时背景基准检查失败（196 通过、1 失败）。当时 host DeviceDpi=96，capture={X=1845,Y=986,Width=192,Height=192}，host={X=1589,Y=766,Width=662,Height=556}。有界等待、消息处理后重设线程 DPI、原生窗口坐标及 BitBlt 捕获都未消除同进程差异；这些试验不能作为生产渲染问题的证据。

最终将同一实际窗口/逐像素断言放到独立 vstest 子进程。父用例既要求子进程退出 0，又要求完成标记，避免过滤器未匹配测试导致假通过；子进程 45 秒看门狗，测试期间不隐藏鼠标。保留背景纯色、捕获位于自有窗口内部、橙色边缘及最低环像素数全部断言。最终 Platform 全套 **197/197** 通过，随后整个方案 **511/511**（Core102、Deployment151、Settings61、Platform197）通过，0 跳过。

测试线程使用与生产程序一致的 PerMonitorV2 坐标环境，并在结束后恢复原线程 DPI 上下文。最初不设置线程 DPI 时纯背景验证失败，说明截图坐标错误；修正测试坐标环境后才验收。最初 Graphics.CopyFromScreen 不接受组合枚举，改用 SourceCopy；最终明确要求实际环的非背景像素超过 100，防止“截图漏掉透明窗口”假通过。

最新捕获实现使用原生 GetWindowRect 与 BitBlt（SRCCOPY | CAPTUREBLT），不再使用上段历史版本的 Graphics.CopyFromScreen。最新全套成功证据目录为 `%TEMP%/FoxMouse.LocatorCompositeTests/439ace8a70db450383e845fc442ac164` 与 `%TEMP%/FoxMouse.LocatorCompositeTests/144948749f3b41fda6918e5ed156378c`。生产文件未修改，现有三类候选包不因测试变化失效。

灰度 24 和 230 两种自有背景均通过：显示环后非背景像素保持橙色通道关系，环中心透出原背景，没有额外灰白描边。人工检查两张实际桌面截图，内外边缘无白圈。
